# HomeMusic — личный музыкальный сервис: требования и план реализации

> Документ — техническое задание для агента-исполнителя. Данные исследования собраны **2026-10-18**.
> Версии, URL и поведение сторонних сайтов перед использованием перепроверить.

---

## 0. Правила для исполнителя

1. Прочитай документ целиком, прежде чем начинать.
2. Работай **по этапам** (раздел 9). Этап закончен, только когда выполнены все его критерии приёмки.
   Проверку проводи реально: запуск, запросы, плеер на телефоне. Одного кода мало.
3. Места, помеченные **[РЕШЕНИЕ]**, — это вопросы к пользователю (раздел 11).
   Задай вопрос до начала работы над соответствующим шагом. Если пользователь не ответил, бери рекомендацию по умолчанию.
4. Секреты (пароли, токены, ключи OpenRouter, WireGuard-ключи) — только в `.env` и в конфигах вне git.
   Шаблоны с пустыми значениями — в `.env.example`.
5. UI и сообщения для пользователя — на русском. Код, идентификаторы и комментарии — на английском.
6. Каждый парсер стороннего сайта покрывай тестами на сохранённых HTML-фикстурах в `hub/tests/fixtures/`.
7. Самостоятельные подзадачи, детали которых пользователю не нужны, делегируй субагентам с effort `high`.
   Пользователю сообщай только итог.

## 1. Цель

Личный аналог Spotify / Яндекс Музыки, который работает на домашнем железе пользователя:

- скачивание музыки из нескольких источников, включая **ru.hitmoz.org** — там есть русские песни без «запиканных» мест;
- загрузка своих аудиофайлов с телефона и группировка их в альбомы по своему усмотрению;
- стриминг на телефон через интернет и сохранение на телефон для прослушивания офлайн;
- ИИ-ассистент: пользователь присылает скриншот (Яндекс Музыка, VK, Spotify, Shazam и т. п.), ассистент находит треки, скачивает их и кладёт в аккаунт пользователя;
- удобные страницы исполнителей и альбомов, как в Spotify: дискография с отметками «есть в библиотеке / нет» и кнопкой «скачать».

## 2. Окружение и ограничения

| Параметр | Значение |
|---|---|
| Телефон | **Android** (iOS не нужен) |
| Сервер | **Домашний ПК, Windows 10 Pro for Workstations**. Здесь работают все сервисы |
| VPS | Слабый. Только **шлюз**: туннель от домашнего ПК и HTTPS-прокси. Тяжёлых сервисов на нём нет |
| Яндекс Плюс | **Нет**. Яндекс Музыку как источник скачивания не используем. Её публичные ссылки — только как источник списка треков |
| ИИ | **OpenRouter**, модель **Claude Haiku 5.5** (точный slug модели взять на openrouter.ai) |
| Пользователи | Минимум один (владелец). Нужна поддержка нескольких аккаунтов: у каждого свои плейлисты и избранное |

## 3. Результаты исследования: почему гибрид, а не готовое решение

### 3.1. Готовые open-source решения не закрывают все требования

| Требование | Что есть готового | Чего не хватает |
|---|---|---|
| Стриминг + офлайн на Android | **Navidrome** + **Tempus** (OSS, бесплатно) или **Symfonium** (платный, лучший офлайн) | Ничего — берём готовое |
| Скачивание из разных источников | yt-dlp, spotDL, Lidarr + Tubifarry, slskd (Soulseek) | Поддержки hitmoz нет нигде. spotDL и YouTube часто подбирают «чистые» (clean) версии |
| Загрузка файлов с телефона, свои альбомы | Веб-загрузка есть в Koel, Ampache, Funkwhale | **Ни один мобильный клиент не умеет загружать файлы.** Navidrome принципиально не принимает загрузки и не редактирует теги |
| Дискография артиста с недостающими альбомами | Aurral, DroppedNeedle (бывший Musicseerr), Lidarr — отдельные приложения на MusicBrainz | MusicBrainz плохо знает русский поп и рэп: у MACAN 12 релизов против 65 на Deezer, у Скриптонита 68 против 112. Ни один плеер не показывает альбомы, которых нет в библиотеке |
| ИИ по скриншотам | Готового нет. Похожие проекты: SpotiArr (ИИ-чат → yt-dlp), Navidrome-MCP, Navicraft | Всё |

**Решение:**
- готовое ядро — **Navidrome** (библиотека, стриминг, транскодирование, пользователи, плейлисты, Subsonic API);
- готовый Android-плеер — **Tempus** или Symfonium;
- **свой сервис «Хаб»**: каталог, загрузчики, загрузка файлов, теги, ИИ;
- **PWA-интерфейс Хаба**, позже — **форк Tempus**, чтобы всё было в одном приложении.

Почему не Koel или Ampache: загрузка файлов у них есть, но нет hitmoz, ИИ и дискографий. Плагинов у Koel нет, значит, пришлось бы форкать. Экосистема клиентов слабее, чем у Navidrome.

Плеер с нуля не пишем. Фоновое воспроизведение, кэш и офлайн-синхронизация — самая дорогая часть, и Tempus её уже решил.

### 3.2. Цензура русских треков — откуда она и как её избегать

- **С 2026-03-01 действуют поправки о «пропаганде наркотиков».** Яндекс Музыка, Звук и VK Музыка удалили тысячи треков или вырезали в них слова. Затронуты, например, Агата Кристи, SCHOKK, Слава КПСС, Pharaoh, Баста/Гуф.
  Часть артистов отредактировала треки **даже на Spotify и Apple Music** (Soda Luv, Yanix, Слава КПСС).
- **Мат по закону не запикивается, а только маркируется 18+.** «Пики» обычно приходят из clean-версий лейблов. Нечёткий матчинг на YouTube (spotDL) часто выбирает именно их.
- **Вывод:** надёжный оригинал — копия, загруженная **до марта 2026**. FLAC сам по себе не гарантирует, что трек без цензуры.
- **Что из этого следует для системы:**
  - выбирать версии с пометкой `Explicit`;
  - при прочих равных брать более раннюю загрузку;
  - никогда не «апгрейдить» существующий файл на более новую версию автоматически (раздел 8.6).

### 3.3. ru.hitmoz.org — проверено, парсинг реален

Проверено 2026-10-18 из Нидерландов: загружались HTML-страницы, выполнялись HEAD-запросы и чтение первых 8 КБ аудиофайла.

**Доступ:**
- Обычный HTML, отдаётся сервером (nginx). Cloudflare и капчи нет.
- **Обязателен заголовок `Accept-Language` с `ru`** (например `ru-RU,ru;q=0.9`). Без него сайт отвечает `403` с пустым телом.
- User-Agent не важен. Cookie `sid` выставляется, но не нужна.
- 15 запросов подряд с интервалом около 0,65 с — ограничений не встретили.

**Поиск:**
- `GET /search?q=<urlencoded>` — 48 результатов на странице.
- Следующие страницы: `/search/start/{48*n}?q=...`.
- Пустой результат: в тексте страницы «По вашему запросу ничего не найдено».

**Селекторы результата поиска:**
- `li.tracks__item[data-musmeta]` — JSON с HTML-экранированием: `{artist, title, url, img, id:"track-id-N"}`.
  `url` — поток 128 kbps, иногда полный `/get/music`. `img` — обложка, `statcore.hitmcdn.com`.
- `a.track__info-l[href^="/song/"]` → `.track__title` (название), `.track__desc` (артист).
- `.track__fulltime` — длительность `mm:ss`.
- `a.track__download-btn[href^="/get/music/"]` — ссылка на 320 kbps. Брать именно тег `a`: у `span` кнопки «лайк» тот же класс.

**Страница трека `/song/{id}`:**
- `h1.p-track-title` — полное название с версией, например `(Soundtrack Version (Explicit))`.
- `select.p-track-select option` — варианты качества. `value` — URL, текст вида `MP3 320Kbps, 12.46 Мб`, есть ещё 128 и 64.
- `.p-track-info__text` — `MP3 320Kbps / 12.46 Мб / 05:26`.

**Ссылки на скачивание:**
- `/get/music/{YYYYMMDD}/{Slug}_{id}.mp3` отвечает `302` на `https://cdnNN.deliciousoranges.com/sN/get/music/...`.
- Хост CDN и шард меняются от файла к файлу. **Всегда следовать редиректу, URL CDN не конструировать.**
- slug сервер игнорирует, но дата должна быть верной. Брать `href` как есть.
- `{YYYYMMDD}` — похоже, дата загрузки на сайт. Использовать как признак «старой» копии (раздел 8.3).
- CDN не требует токена, срока действия, referer или cookie. Ответ: `audio/mpeg`, `Content-Length`, `Accept-Ranges: bytes`.
- `/get/cuts/...` — транскодированные потоковые версии 128 и 64 kbps. Для скачивания не использовать.

**Качество и теги:**
- Обычно 320 kbps, иногда 192.
- ID3v2.3. В старых загрузках есть название, артист, альбом, год и обложка (около 34 КБ). В новых — только название и артист.
- **Всегда перетегировать** своими данными (раздел 8.4).

**Каталог:**
- `/artist/{id}` (страницы `/artist/{id}/start/{n}`) и `/album/{id}`. Заголовок альбома `h1.p-info-title` — «Название (Год)».
- Картинки артистов и альбомов — с `avatars.yandex.net`.
- Списки: `/albums`, `/genre/{id}`, `/songs/top-today`, `/songs/new`.

**Зеркала:**
- `rus.hitmotop.com` (301) и `hitmos.me` (302) ведут на `ru.hitmoz.org`.
- `rus.hitmos.fm` — **другой бэкенд**: другие ID и другая вёрстка.
- `hitmo.lol` — посторонний клон.

**Качество выдачи:**
- Много дублей, каверов, караоке, минусовок.
- Пометка Explicit есть только в `h1` страницы трека, в списке поиска её нет.
- Пробелы в каталоге: например, «noize mc» не находится.

**robots.txt** запрещает `*q=*`, `/get/` и `/cover/`. Подробнее — в разделе 10.

**Запасной источник — `rus.hitmos.fm`:**
- Next.js, без проверки языка.
- Поиск: `/search?q=`. Селекторы: `a.track-item__title[href^="/song/"]`, `a.track-item__artist`, `.track-item__duration`.
- MP3-ссылки лежат в RSC-пейлоаде страницы: `https://dwc1.hitmos.fm/{base64("/mp3/{id}/Artist - Title (hitmos.fm).mp3")}.mp3`.
  `dwc1` — для скачивания, `plc1` — для проигрывания. Около 320 kbps, без токена.

Другие русские сайты (muzofond, mp3party, musify, z3.fm и т. п.) из NL недоступны (403 или 451) или рендерят выдачу через JS.
drivemusic.me отдаёт ссылки, которые истекают примерно через сутки, качество около 192 kbps. Их пока не берём.

Готовые парсеры на GitHub для справки (все маленькие, 0–3 звезды): `Shukurov777/hitmoz-parser`, `JoyHubN/pars_hitmos`, `nshib00/jademusic-api`, `BananfonBan/hitmo-downloader`.

### 3.4. Остальные источники

- **yt-dlp** — живой, релиз 2026.08.19.
  - **Для YouTube с июня 2026 нужен Deno 2.3+ или Node 22+.**
  - Звук с потерями: Opus около 160k.
  - Подходит для международной музыки и того, что есть только на YouTube.
- **spotDL** — не используем: подбирает треки нечётко, 128 kbps, Spotify API урезан в 2026 году.
- **Soulseek через slskd** — лучший путь к FLAC и старым оригинальным рипам. Опционально, этап 5.
- Deezer, Qobuz, Tidal, Яндекс, Звук требуют платных аккаунтов. Не используем.

### 3.5. Метаданные и каталог

- **Deezer public API** — основной каталог.
  - Без ключа, хорошо покрывает русскую музыку.
  - Есть `explicit_lyrics`, ISRC, UPC, обложки до 1000 px и типы релизов album/single/ep/compile.
  - Лимит около 50 запросов за 5 секунд с одного IP.
  - **Доступность из РФ/РБ не проверена.** Если не открывается с домашнего ПК, пускать запросы каталога через VPS (раздел 8.1).
- **hitmoz** `/artist` и `/album` — второй каталог для русской музыки.
- **MusicBrainz** — опционально, ради MBID. Не чаще 1 запроса в секунду, обязателен User-Agent.
- Spotify Web API не использовать: в 2026 году урезан, для приложений разработчика нужен Premium.

### 3.6. Доступ к ИИ

- **Claude Haiku 5.5:** $0.10 за 1 млн входных токенов, $0.50 за 1 млн выходных.
  Скриншот 1080×2400 — около 3,4 тыс. токенов, то есть **меньше $0.001 за скриншот**.
- **Риск:** Anthropic официально не работает в России и Беларуси. По неофициальным данным, OpenRouter в мае–июле 2026 закрыл закрытые модели для российских аккаунтов.
  У пользователя доступ есть, но провайдер обязан быть **настраиваемым**. Подходит любой OpenAI-совместимый `base_url` и `model`.
- **Запасные варианты:**
  - локальная **qwen3-vl:8b** через Ollama — около 6 ГБ, нужна видеокарта на 8+ ГБ;
  - **Yandex AI Studio** (Qwen3.5-35B VL, OpenAI-совместимый API).
- **Telegram-бот как основной интерфейс не подходит:** в России с февраля 2026 его сильно замедляют, особенно загрузку медиа.
  Основной путь — Android «Поделиться» → наше приложение. Для PWA это Web Share Target.

## 4. Функциональные требования

У каждого требования есть ID и критерий приёмки (КП).

### FR-1. Аккаунты
- Вход в Хаб — по логину и паролю **Navidrome**, один аккаунт на всё. Пользователей создаёт админ в Navidrome.
- Плейлисты, избранное и история ассистента — у каждого пользователя свои.
- **КП:** два пользователя видят общую библиотеку. Каждый видит только свои плейлисты и свои задачи ассистента.

### FR-2. Стриминг и офлайн
- Стриминг с домашнего сервера через интернет (мобильная сеть) по HTTPS.
- Скачивание альбомов и плейлистов на телефон, прослушивание без интернета.
- **КП:**
  - на LTE трек начинает играть меньше чем за 3 с;
  - скачанный плейлист играет в режиме полёта;
  - новый трек, добавленный в плейлист, синхронизируется на телефон.

### FR-3. Поиск и скачивание из интернета
- Единый поиск по каталогу (Deezer + hitmoz) и по библиотеке.
- Скачать можно трек, альбом или всю дискографию.
- Порядок источников настраивается, есть автоматический fallback (раздел 8.3).
- Очередь загрузок со статусами: `queued / searching / downloading / tagging / importing / done / failed / needs_review`.
  Можно повторить загрузку или вручную выбрать другого кандидата.
- Дедупликация: трек, который уже есть в библиотеке, повторно не качается, а связывается с существующим.
- **КП:**
  - «Кино — Группа крови» после нажатия «Скачать» появляется в Navidrome и в плеере на телефоне меньше чем за 60 с, с обложкой и правильными тегами;
  - повторное скачивание не создаёт дубль.

### FR-4. Каталог как в Spotify
- **Страница исполнителя:** фото, топ-треки, дискография по группам: «Альбомы», «Синглы и EP», «Сборники».
  Сортировка по дате, новые сверху. У каждого релиза обложка, год и бейдж «в библиотеке» / «частично» / «нет».
  Кнопки «Скачать» и «Скачать всю дискографию».
- **Страница альбома:** треклист с длительностью, бейджами `E` (explicit) и статусом «есть / нет».
  Кнопки «Скачать альбом», «Скачать трек», «В плейлист».
- «Сохранить в мою коллекцию» — звёздочка (`star`) в Navidrome у текущего пользователя.
- **КП:** у артиста с релизами в Deezer, например «Три дня дождя», дискография совпадает с Deezer, а бейджи правильно показывают, что уже есть в библиотеке.

### FR-5. Свои файлы и альбомы
- Загрузка нескольких аудиофайлов с телефона: `mp3, m4a/aac, flac, ogg/opus, wav`. До 500 МБ на файл.
- Загрузка через выбор файлов в приложении и через Android «Поделиться» → Хаб.
- Форма импорта:
  - теги из файла подставляются в поля;
  - файлы можно отправить в **существующий альбом** (поиск по библиотеке) или в **новый** (название, исполнитель альбома, год, обложка);
  - любой тег трека можно поправить.
- Редактирование библиотеки: переименовать альбом, перенести треки между альбомами, сменить обложку, собрать свой альбом-подборку из любых треков.
- **КП:** загруженные с телефона 5 файлов оказываются в одном новом альбоме с моей обложкой. После этого альбом виден в Tempus, и его можно скачать для офлайна.

### FR-6. ИИ-ассистент
- **Вход:** один или несколько скриншотов, ссылка (плейлист или альбом Яндекс Музыки, плейлист YouTube) или текст («скачай последний альбом X»).
- **Конвейер** (раздел 8.5): распознать → найти в каталоге → **показать карточку подтверждения** → скачать → добавить в плейлист пользователя.
- В карточке:
  - треки с уверенным совпадением отмечены сразу;
  - для сомнительных показаны 3 варианта на выбор;
  - нераспознанные можно исправить вручную.
- Цель по умолчанию — новый плейлист «Со скриншота {дата}». Можно выбрать существующий плейлист или «только в библиотеку».
- Сначала работает именно этот фиксированный конвейер. Свободный чат с инструментами — вторая очередь, этап 3.8.
- **КП:**
  - на тестовом наборе из 30+ скриншотов не меньше 90 % строк найдены правильно;
  - ни один трек не скачивается без записи из каталога и без подтверждения, если уверенность низкая.

### FR-7. Уведомления
- Статусы загрузок на сервер видны в разделе «Загрузки» и обновляются через SSE.
- Веб и Android уведомляют о задачах ассистента, которые ждут подтверждения или завершились ошибкой.

## 5. Нефункциональные требования

- **NFR-1.** Вся тяжёлая работа — на домашнем ПК. На VPS только WireGuard и Caddy, суммарно меньше 150 МБ RAM.
- **NFR-2.** После перезагрузки ПК все сервисы и туннель поднимаются сами.
  Docker Desktop в автозапуске, контейнеры с `restart: unless-stopped`, WireGuard как служба Windows.
  Сон ПК отключён.
- **NFR-3.** Наружу ничего не открывается без аутентификации. Только HTTPS. Пароли стойкие.
- **NFR-4.** Бережная нагрузка на сторонние сайты.
  - hitmoz: не больше 1 запроса в секунду и не больше 2 параллельных загрузок.
  - Экспоненциальный backoff на 403, 429 и 5xx.
  - Кэш результатов поиска и каталога.
- **NFR-5.** Устойчивость к смене доменов и вёрстки.
  - Домены хранятся в конфиге списком, есть health-check.
  - Ломающиеся парсеры обнаруживают тесты на фикстурах и периодический smoke-тест.
- **NFR-6.** Логи в stdout (JSON). Эндпоинт `/healthz`. Резервная копия SQLite-базы Хаба и данных Navidrome раз в сутки.
- **NFR-7.** Конфигурация — через `.env` и `config.yaml`. Версии Docker-образов закреплены (pinned).

## 8. Ключевые механизмы

### 8.1. Сеть и шлюз

**VPS:**
- WireGuard-сервер `10.8.0.1/24`, порт UDP 51820.
- Caddy:
  ```
  music.<домен> { reverse_proxy 10.8.0.2:4533 }
  hub.<домен>   { reverse_proxy 10.8.0.2:8080 }
  ```
- Домена нет → использовать `<ip-vps>.sslip.io` (сертификат Let's Encrypt выпускается автоматически). **[РЕШЕНИЕ]**
- Опционально — лёгкий HTTP-прокси (tinyproxy), слушает только `10.8.0.1`. Нужен, если Deezer API недоступен напрямую с ПК.
  Хаб использует его только для хостов из `CATALOG_PROXY_HOSTS`.

**Домашний ПК:**
- WireGuard-клиент `10.8.0.2`.
- Docker публикует порты 4533 и 8080 на хосте.
- Правило Windows Firewall: входящие на 4533 и 8080 разрешены только из `10.8.0.0/24` и локальной сети.

Права:
- Navidrome монтирует `MUSIC_ROOT/library` только для чтения.
- Хаб монтирует `MUSIC_ROOT` с записью.

**Особенность Windows:** при bind-монтировании из Windows в WSL2 события inotify не доходят. Файловый watcher Navidrome не сработает.
- Хаб после каждого импорта сам вызывает `startScan` и ждёт окончания через `getScanStatus`.
- Дополнительно `ND_SCANSCHEDULE=1h`.

### 8.2. Интерфейс источника

```python
class TrackQuery(BaseModel):
    artist: str; title: str
    album: str | None = None; duration_s: int | None = None
    isrc: str | None = None; explicit: bool | None = None
    version: str | None = None          # remix/live/... если запрошено явно

class Candidate(BaseModel):
    provider: str; provider_id: str
    artist: str; title: str; duration_s: int | None
    bitrate_kbps: int | None; explicit: bool | None
    upload_date: date | None; page_url: str; download_url: str | None
    cover_url: str | None; score: float = 0

class Provider(Protocol):
    name: str
    async def search(self, q: TrackQuery, limit: int = 10) -> list[Candidate]: ...
    async def enrich(self, c: Candidate) -> Candidate: ...   # например, страница трека hitmoz: h1 с Explicit, битрейт
    async def fetch(self, c: Candidate, dest_dir: Path) -> Path: ...
```

### 8.3. Выбор источника и кандидата

**Порядок источников** настраивается в `config.yaml`:
- **русская музыка** — в артисте или названии есть кириллица, релиз из СНГ, либо пользователь явно указал `ru`:
  `hitmoz → hitmos_fm → soundcloud (загрузки до 2026-05-01) → yt_reupload (перезаливы YouTube) → ytdlp`:
  официальные копии YouTube Music после закона часто отредактированы (раздел 3.2), поэтому они последние;
- **остальная музыка:** `ytdlp (YouTube Music) → hitmoz → (slskd)`.

**Отбор кандидатов:**
1. Нормализация (раздел 8.5.3) артиста и названия у запроса и у кандидата.
2. Жёсткие фильтры:
   - артист совпадает после нормализации, коэффициент не меньше 0,9;
   - длительность отличается не больше чем на 3 с (если в каталоге она известна);
   - отсеиваются `караоке|минус|instrumental|кавер|cover|remix|slowed|speed up|sped up|nightcore|8d`, если их нет в запросе.
3. Сортировка:
   1. score;
   2. `explicit=True`, если в каталоге трек explicit или пользователь не просил clean;
   3. битрейт не ниже 320;
   4. **более ранний `upload_date`** (для hitmoz — дата из `/get/music/{YYYYMMDD}/`; загрузки до 2026-03-01 получают бонус).
4. Для 3 лучших кандидатов hitmoz вызывается `enrich()`: страница трека, `h1` с `Explicit`, реальный битрейт.

**Проверки после скачивания:**
- `ffprobe`: файл открывается, длительность в пределах ±3 с;
- битрейт сохраняется в базу;
- `silencedetect`: тишина длиннее 0,7 с в середине трека даёт **предупреждение** «возможно, запикано». Трек при этом не отклоняется.
- Проверка провалилась → берётся следующий кандидат или следующий источник.
- Кандидатов не осталось → статус `needs_review`. Пользователь выбирает вручную из `candidates_json` или вставляет ссылку.

### 8.4. Теги и импорт

- **mutagen**, ID3v2.4 UTF-8 для mp3, нативные теги для m4a, flac и opus.
- **Поля:**
  - `title`, `artist`, `albumartist`, `album`, `tracknumber`, `discnumber`, `date`, `genre`, `isrc`;
  - обложка: Deezer `cover_xl`, иначе hitmoz `img`; JPEG до 1000 px;
  - `ITUNESADVISORY`: 1 — explicit, 2 — clean;
  - TXXX: `HOMEMUSIC_SOURCE`, `HOMEMUSIC_SOURCE_URL`, `HOMEMUSIC_SOURCE_DATE`, `HOMEMUSIC_ACQUIRED`, `DEEZER_TRACK_ID`, `DEEZER_ALBUM_ID`.
- **Одиночный трек без альбома в каталоге:** `album = title`, тип single.
- **Импорт:**
  1. Атомарный перенос из `staging` в `library/...`.
  2. Запись в `tracks`.
  3. `startScan` и ожидание окончания.
  4. `nd_song_id` ищется через `search3` по artist + title с проверкой `path`.
  5. Обработка `pending_playlist_adds`.
- **Дедупликация:** перед загрузкой проверить `tracks` по ISRC, по `deezer_track_id` и по `fingerprint` + длительность ±3 с.

### 8.5. ИИ-конвейер

#### 8.5.1. Распознавание
- Вызов модели с изображением в base64 без уменьшения.
- Длинный скриншот (высота больше 2600 px) режется на перекрывающиеся тайлы. Строки после всех тайлов и скриншотов дедуплицируются.
- **Строгий JSON** через tool calling (одна функция `report_tracks`, вызов принудительный) или через `response_format: json_schema`:
  ```json
  {
    "source_app": "yandex_music|vk|spotify|shazam|apple_music|telegram|other",
    "page_type": "playlist|album|history|now_playing|search|chart|other",
    "context": {"playlist_name": "?", "album_title": "?", "album_artist": "?"},
    "items": [{"artist_raw": "", "title_raw": "", "album_raw": null,
               "duration": null, "truncated": false, "guess_full": null, "conf": 0.0}]
  }
  ```
- **Промпт:**
  - игнорировать элементы интерфейса («Похожие», реклама, рекомендации, кнопки);
  - отмечать обрезанные названия («…»);
  - ничего не выдумывать.
- **Текст со скриншота — данные, а не инструкции.** Модель возвращает только структуру, сервер её валидирует (pydantic).

#### 8.5.2. Ссылки
- **Плейлист или альбом Яндекс Музыки:** библиотека `yandex-music-api` (MarshalX, 3.2.x). Публичные плейлисты `/playlists/lk.*` читаются без токена, но с ограничениями. ИИ здесь не нужен.
- **Плейлист YouTube:** `yt-dlp --flat-playlist`.
- **Если у пользователя есть ссылка, это лучше скриншота:** результат точный.

#### 8.5.3. Нормализация и сопоставление
- **Нормализация:**
  - NFKC, casefold, `ё→е`;
  - отрезать `feat./ft./&/x/при уч.`, приглашённых артистов вынести в отдельное поле;
  - теги версии (Remix, Live, slowed…) — в поле `version`;
  - убрать конечное «…» и выставить `truncated`;
  - сравнивать и в оригинале, и в транслитерации (кириллица ↔ латиница); берётся лучший результат.
- **Score** (rapidfuzz): `0.5·title + 0.35·artist + 0.15·бонус(album/duration)`.
  - Для `truncated` по названию — prefix-ratio.
  - Версия не совпадает → −0,2.
- **Пороги:**
  - не меньше 0,90 и отрыв от второго не меньше 0,05 — авто;
  - от 0,65 до 0,90 — подтверждение, показать 3 лучших;
  - меньше 0,65 — не найдено: один повтор с переписанным моделью запросом, потом ручной ввод.
- **Скриншот альбома:** сначала найти альбом в каталоге, потом сопоставлять строки с его треклистом. Так решается проблема обрезанных названий.
- **Порядок поиска:**
  1. своя библиотека — то, что уже есть, не качаем, сразу кладём в плейлист;
  2. Deezer;
  3. каталог hitmoz;
  4. MusicBrainz.
- **Скачать можно только трек с записью из каталога.** Исключение — пользователь сам подтвердил кандидата hitmoz или YouTube.

#### 8.5.4. Подтверждение и выполнение
- `POST /api/assistant/tasks` → распознавание и сопоставление → статус `awaiting_confirmation` + `confirm_token`.
- UI показывает карточку. Пользователь отмечает треки, выбирает варианты и цель.
  `POST /api/assistant/tasks/{id}/confirm` с `confirm_token` → `download_batch`.
- Операции с побочными эффектами (скачивание, плейлисты) выполняются **только по confirm_token из UI**, а не по слову модели.

| 0.1 | Проверить, что на ПК установлены Docker Desktop (WSL2 backend) и Git. Выбрать диск и путь `MUSIC_ROOT` **[РЕШЕНИЕ]**. Отключить сон ПК в схеме питания |
| 0.2 | `docker-compose.yml` с Navidrome: закреплённая версия, `ND_SCANSCHEDULE=1h`, `ND_DEFAULTLANGUAGE=ru`, том `library` только для чтения, `restart: unless-stopped`. Создать админа и пользовательский аккаунт |

| 0.4 | ПК: WireGuard для Windows как служба с автозапуском, `PersistentKeepalive=25`. Правила Windows Firewall для портов 4533 и 8080 |
| 0.5 | Телефон: поставить Tempus (или Symfonium **[РЕШЕНИЕ]**), подключить `https://music.<домен>`. Положить в `library/` несколько тестовых альбомов |
| 0.6 | `README.md`: как поднять всё с нуля и как обновлять |

**Критерии приёмки:**
- трек играет на телефоне через мобильную сеть;
- альбом, скачанный в Tempus, играет в режиме полёта;
- после перезагрузки ПК всё работает без ручных действий;
- на VPS Caddy и WireGuard занимают меньше 150 МБ RAM.

## 10. Риски и меры

| Риск | Мера |
|---|---|
| hitmoz меняет домен, вёрстку или проверку языка | Список доменов + health-check, тесты на фикстурах, ежедневный smoke-тест; fallback — hitmos.fm и yt-dlp |
| Юридическая сторона: контент hitmoz нелицензионный, `robots.txt` запрещает автоматический поиск и скачивание | Только личное использование. Бережные лимиты (NFR-4). Скачанное не раздаётся. Хаб не открыт без аутентификации. Пользователь принимает этот риск сам |
| Новые загрузки на любых сервисах могут быть отредактированы (закон 2026-03-01) | Предпочтение Explicit и ранним загрузкам, `locked` для оригиналов (8.6), предупреждение по `silencedetect` |
| OpenRouter или Anthropic перестанут быть доступны из региона | LLM-провайдер настраивается через `.env`; fallback — Ollama `qwen3-vl:8b` или Yandex AI Studio |
| Deezer API недоступен из РФ/РБ | Прокси через VPS (8.1); fallback — каталог hitmoz |
| yt-dlp ломается после изменений YouTube | Регулярно обновлять образ (еженедельная пересборка); Deno внутри образа |
| Windows: сон, перезагрузки Windows Update, нет inotify в bind mount | Отключить сон, автозапуск, явный `startScan` после импорта, расписание сканирования |
| ID треков Navidrome меняются после ретега или переноса | Проверить на шаге 2.6; при необходимости пересвязывать плейлисты по `path` |
| Слабый VPS упирается в канал при стриминге | 320 kbps — это около 40 КБ/с на поток, нагрузка мала. При нехватке включить транскодирование в Navidrome (opus 128) для мобильной сети |

## 11. Решения, которые нужно получить от пользователя

| # | Вопрос | Рекомендация по умолчанию |
|---|---|---|
| D1 | Где хранить музыку (`MUSIC_ROOT`), какой диск и сколько места | Отдельная папка на самом большом диске, например `B:\Music` |
